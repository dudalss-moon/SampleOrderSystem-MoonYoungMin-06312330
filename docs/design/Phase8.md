# Phase8: DB 연동 (인메모리 → H2 JDBC)

## 1. 기능 개요

현재 인메모리(`LinkedHashMap` / `LinkedList`) 기반의 저장소를 H2 임베디드 DB + JDBC로 교체.
애플리케이션 재시작 후에도 데이터가 유지되며, 기존 서비스·UI 레이어는 수정 없이 동작.

### 변경 범위 요약

| 레이어 | 변경 내용 |
|--------|-----------|
| `domain` | `ProductionJob.restore()` 정적 팩토리 추가 |
| `repository` | 인터페이스 추출 + InMemory / Jdbc 구현 분리 |
| `db` (신규) | `DatabaseConfig`, `SchemaInitializer` 추가 |
| `service` | `ProductionService` — job 진행 후 `save()` 호출 추가 |
| `Main` | JDBC 구현체 주입으로 교체 |
| `build.gradle` | H2 의존성 추가 |

---

## 2. 기술 선택

| 항목 | 결정 | 이유 |
|------|------|------|
| DB | H2 (embedded) | 서버 불필요, 순수 Java, 파일 기반 영속성 |
| 접근 방식 | JDBC (raw) | ORM 없이 기존 코드 스타일 유지, 의존성 최소화 |
| 운영 모드 | `jdbc:h2:file:./data/ssemi` | 프로젝트 루트 `data/` 디렉토리에 파일 저장 |
| 테스트 모드 | `jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1` | 테스트마다 인메모리 격리 |

## 4. 인터페이스 설계

### SampleRepository (interface)
```java
public interface SampleRepository {
    void save(Sample sample);
    Optional<Sample> findById(String id);
    List<Sample> findByName(String keyword);
    List<Sample> findAll();
    boolean existsById(String id);
    boolean existsByName(String name);
    int count();
    int totalStock();
}
```

### OrderRepository (interface)
```java
public interface OrderRepository {
    void save(Order order);
    Optional<Order> findById(String orderId);
    List<Order> findByStatus(OrderStatus status);
    List<Order> findAll();
    String generateId();
}
```

### ProductionQueueRepository (interface)
```java
public interface ProductionQueueRepository {
    void enqueue(ProductionJob job);
    Optional<ProductionJob> peek();
    Optional<ProductionJob> dequeue();
    List<ProductionJob> getQueue();
    void save(ProductionJob job);    // ← 신규: 생산 진행 상태 갱신용
    String generateJobId();
}
```

> `save(ProductionJob)` 추가 이유: `processProduction()` 호출 시 `producedQty` 변경을
> DB에 반영해야 하므로 추가. InMemory 구현은 객체 참조로 이미 반영되므로 no-op.

## 5. DB 스키마

```sql
CREATE TABLE IF NOT EXISTS samples (
    id                  VARCHAR(50)  PRIMARY KEY,
    name                VARCHAR(100) NOT NULL,
    avg_production_time INT          NOT NULL,
    yield               DOUBLE       NOT NULL,
    stock               INT          NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS orders (
    order_id       VARCHAR(20)  PRIMARY KEY,
    sample_id      VARCHAR(50)  NOT NULL REFERENCES samples(id),
    customer_name  VARCHAR(100) NOT NULL,
    quantity       INT          NOT NULL,
    status         VARCHAR(20)  NOT NULL,
    stock_deducted BOOLEAN      NOT NULL DEFAULT FALSE
);

CREATE TABLE IF NOT EXISTS production_jobs (
    job_id        VARCHAR(20) PRIMARY KEY,
    order_id      VARCHAR(20) NOT NULL REFERENCES orders(order_id),
    target_qty    INT         NOT NULL,
    produced_qty  INT         NOT NULL DEFAULT 0,
    total_time    INT         NOT NULL,
    enqueue_order BIGINT GENERATED BY DEFAULT AS IDENTITY  -- FIFO 정렬 기준
);

CREATE TABLE IF NOT EXISTS sequences (
    name     VARCHAR(50) PRIMARY KEY,
    next_val INT         NOT NULL DEFAULT 1
);
-- 초기 시퀀스 레코드
MERGE INTO sequences (name, next_val) KEY (name) VALUES ('order', 1);
MERGE INTO sequences (name, next_val) KEY (name) VALUES ('job',   1);
```

### JdbcProductionQueueRepository
```java
public final class JdbcProductionQueueRepository implements ProductionQueueRepository {
    // enqueue(): INSERT INTO production_jobs
    // peek():    SELECT ... ORDER BY enqueue_order ASC LIMIT 1
    // dequeue(): DELETE ... WHERE job_id = (peek)
    // getQueue(): SELECT ... ORDER BY enqueue_order ASC (except head)
    // save():    UPDATE produced_qty WHERE job_id
    // generateJobId(): SELECT/UPDATE sequences WHERE name='job'
}
```

## 7. 데이터 매핑

### Order 재구성 시 객체 그래프
DB에서 `orders` 조회 시 `sample_id`로 `samples`를 JOIN하여 `Sample` 객체를 함께 복원.

```sql
SELECT o.*, s.id, s.name, s.avg_production_time, s.yield, s.stock
FROM orders o
JOIN samples s ON o.sample_id = s.id
WHERE o.order_id = ?
```

### ProductionJob 재구성 시 객체 그래프
`production_jobs`를 조회할 때 `orders`와 `samples`를 JOIN하여 전체 객체 그래프 복원.

```sql
SELECT pj.*, o.*, s.*
FROM production_jobs pj
JOIN orders  o ON pj.order_id  = o.order_id
JOIN samples s ON o.sample_id  = s.id
ORDER BY pj.enqueue_order ASC
```
